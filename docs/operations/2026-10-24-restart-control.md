## 为什么超时必须是挂死，而不是谓词拒绝

`EnumaDispatchDetailCheckpoint` 只在 StartImage **返回**后按 status 选门：`step N / query 1` 仅在 status 等于该查询的"通过"编码时才 `EnumaStageCheckpoint(13)`，query 2 仅在等于"拒绝"编码时才命中。两条编码都没出现，就说明 SimpleFb **没有返回预期 status**，而不是"谓词不满足"。

于是超时只剩两个出口：

1. **复位出口失效** —— `EnumaStageCheckpoint` 走 `MicroSecondDelay` → `ResetCold()`（PSCI SYSTEM_RESET）→ `CpuDeadLoop()`。若 PSCI 既不返回也不复位，就永久停住，表现正是黑屏 + 无 ADB + 无 fastboot 枚举 + 只能长按，与 `out/camera-capture/20261024T160517`、`20261024T162234` 两张全黑快照一致。
2. **SimpleFb 内显示 MMIO 读挂死** —— 探针读 `0x0ae00000..0x0ae84207`，MDP 窗口未上电或映射失效时可能触发未处理异常，StartImage 永不返回。

两者在现有通道下**原理上不可区分**，因为通道只在"复位成功"时才有信号。

## 下一步的区分实验

做一份**不含任何显示 MMIO 读、不含等待**的早期停止点候选，重复多笔观察：

- 稳定成功 → 锁定 MMIO 读，下一步查 MDP 上电/时钟门控与 R-004 映射的时序关系；
- 同样偶发挂死 → 锁定复位出口，下一步换出口（改走 warm reset、由 BootShim 兜底，或干脆不主动复位而让正常启动继续）。

这也是 STATUS 之前定的"更早停止点定位"，现在它从"要不要定位早期路径"升级为"唯一能分开两个出口的实验"。
