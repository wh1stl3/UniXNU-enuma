## 每轮如何执行

1. 定位当前官方步骤和本轮要完成的能力；核对已有结果，避免重复宣称或重复试验。
2. 收集enuma硬件事实，选择可复用组件并锁定来源。将通用、SoC、板级和OS ABI责任分开，不把其他设备配置当成本机证据。
3. 按依赖推进实现。每个驱动明确硬件资源、传输协议、超时/失败、CPU/DMA内存、OS服务接口，以及源码→归档→链接→初始化调用链。组件被选择或对象可编译都不等于已集成。
4. 按当前固定版本支持的官方构建入口组织产物；自有适配器记录其原因、输入和等价验证。官网新字段/命令先检查版本兼容性，不悄悄放松旧锁或删除example标志来绕过条件。
5. 分别记录宿主、QEMU和硬件结果。失败保留当时镜像、摘要及最后可确认日志；更改输入后重新验证相关产物。启动参数改变必须反映在实际payload/boot包中。
6. 更新STATUS、HANDOFF、工作日志和适配记录。发布或设备测试只在用户当前授权及本仓门禁范围内进行。

以上是本仓对官方流程的执行安排；不新增逐步审批，也不把官方示例命令直接发给设备。

## 按官方启动阶段标记当前进度

| 阶段 | enuma当前边界 |
| --- | --- |
| UEFI / UniXNU | 已有历史临时显示/菜单证据；OEM运行版仍未启动，生产显示、正常BDS和输入未验收 |
| Payload | 新FAT及文件回读通过；不等于本机启动时发现载荷卷 |
| DarwinBoot | 有离线契约验证；新完整系统尚无本机EBS/内核跳转证据 |
| XNU | 新30组件预链接及格式检查通过；没有本机内核运行结论 |
| Storage/root | 本地OS/SystemOS组件文件、SMMU/SCSI组件和宿主测试完成；IOKit UFS/PMGR、stream归属、卷策略/UUID和实际挂根仍需接入验证 |
| Userland | Data seed、launchd、图形服务及SpringBoard尚未闭环；不能由根镜像存在推断桌面可用 |

当前优先事项是补齐真实驱动集成与根卷/Data依赖，同时维护载荷运输和日志通路。允许独立离线工作继续，但验收按依赖逐层记录，不能跨层填成功。
