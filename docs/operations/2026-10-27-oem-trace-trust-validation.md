# D-322：追踪记录可信性离线验证

用户要求先验证透明转发、嵌套配对、缺失返回与日志丢失，禁止把没有返回记录判成驱动死锁。实机仍暂停，本轮无设备操作、镜像推送、提交推送或nuwa操作。

最终证据out/oem-service-trace-20261027/trust-check2/result.json：5条命令全部通过，包含宿主ASan/UBSan、C回放到Python解码往返、7项Python测试及AArch64对象/服务偏移/LR指令检查。7项用例中的生成测试涵盖32组序列×10个快照边界，共320个独立模型对照，检查环形容量前后、嵌套与返回交错、仍可见入口无返回以及入口已覆盖的孤立返回。不是320次实机或原厂PE执行。

透明转发：成功/警告/错误状态按原服务返回；参数、输出指针及失败时保持输出不变的行为与原调用一致；各实际服务调用不处于记录器的高TPL临界区。新增空GUID失败对照，未将原EFI_INVALID_PARAMETER改成成功。已有测试继续覆盖CRC拒绝、错误目标/代码类型、上下文生命周期、环形覆盖与计数耗尽。

归因：仅按同一call ID及服务、RVA、GUID、value一致性配对。内层返回不关闭外层调用。缺行、重复、乱序、错误参数/服务/RVA配对拒绝解码，不填补状态。环形覆盖数量明确；孤立返回标识入口不在保留窗口，不能推造入口时间或参数。输出端即便已写出部分字符再拒绝，游标仍不推进且函数不自动重试，避免默默跳行或重复输出。

解码增加assessment.deadlock_established=false及missing_return="not observed in this snapshot"；计数耗尽另行标识。未返回记录可能对应快照时仍在运行、异常/非局部退出、记录停止或取证缺口，单独不能建立驱动死锁。若显示某个API入口后未见返回，只能把它列作后续取证区间，必须结合精确PE、启动身份、调用覆盖与其它证据。

组件仍未加入固件profile/Core入口，尚未运行OEM DisplayDxe，也未解决卡死时可靠取出RAM日志的问题。R022—R027全部冻结资格及其产物摘要复核保持不变；原check3/trust-check1结果保留历史字节，新验证写独立目录。报告reports/enuma-oem-trace-trust-validation.json。后续用于缩小DisplayDxe位置之前，还需精确Core接线及可观测的取证出口，不以当前宿主夹具推断实机卡点。
