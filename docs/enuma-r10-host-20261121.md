# enuma r10 path probe — host candidate

`self-checked`; no device operation, independent verifier, or deep review.
The isolated candidate extends r9; the default patch series is unchanged.

## Probe and interpretation

The r9 six paths, filesystem and timebase probes remain. The additional
lookups use the same once-only gate, `vfs_context_current()` and `printf`
format. Labels beginning `...` omit the indicated leading or intermediate
components **only in the printed label**; lookups use the full paths.

| Full path | Printed label if shortened | Interpretation |
| --- | --- | --- |
| `/System/Library/CoreServices/SpringBoard.app` | unshortened | DIR tests the app directory in the pre-exec view. |
| `/System/Library/CoreServices/SpringBoard.app/SpringBoard` | `.../CoreServices/SpringBoard.app/SpringBoard` | REG tests presence of the SpringBoard executable path in that view. |
| `/usr/libexec/CommCenter` | unshortened | REG tests presence of the CommCenter executable path. |
| `/System/Cryptexes/OS/System/Library/dyld` | unshortened | DIR tests the cryptex dyld directory view. |
| `/System/Cryptexes/OS/System/Library/dyld/dyld_shared_cache_arm64e` | `.../Cryptexes/OS/.../dyld/dyld_shared_cache_arm64e` | REG tests the cryptex cache path. |
| `/System/Library/Caches/com.apple.dyld/dyld_shared_cache_arm64e` | `.../Caches/com.apple.dyld/dyld_shared_cache_arm64e` | REG tests the alternate cache path. |

Expected types are hypotheses, not observed existence. ENOENT indicates lookup
failure in this context, not necessarily absence from every mounted view.
Successful executable lookup distinguishes path presence in this view from an
ENOENT here; neither result proves or excludes a later service-domain or
sandbox rejection, or proves executability. The probe does not run as the
later service. Each new output line is under 80 characters even using a
10-digit errno and `OTHER`.

## Packaging corrections

The first run failed because `seed-inspection.json` was in `self-check/`, not
`self-check/build-final/`; it was copied to the latter as in r9. A retry
first hit the existing output directory; failed directories were renamed and
retained. Next the inherited expected replacement set omitted `kern_exec.o`:
the set is relative to r4, not the r9 delta, and now contains
`bsd_init.o`, `IOUserClient.cpo`, and `kern_exec.o`. Only kern_exec differs
from r9; bsd_init is r8 reuse, IOUserClient is the r8 display unit.
Finally the report assumed every replaced object had a display macro.
Display assertions now cover only bsd_init and IOUserClient; the probe group
asserts `#define XNU_ENUMA_PATH_PROBE 1` in kern_exec's saved preprocessor
output, and both groups are printed. The unchanged objects are byte-compared
against r9 and kern_exec's r9/r10 hashes are pinned.

No runtime existence, permissions, launchd outcome, display output, persistent
storage, device behavior, independent verification or review is established.
