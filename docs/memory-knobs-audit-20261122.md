## 三项判断

1. 同一段完全以最小页映射、表项均为 8 字节的密集映射中，4K 页比 16K 页约用 **4 倍叶表项存储**：1 GiB 分别约 2 MiB 和 512 KiB。此理论值不含上级表、块映射、共享和稀疏映射，不是实测总开销。bootstrap 使用另一套早期块映射预算；16 页补丁按最多 6 GiB 设计，r22 2720 MiB 在设计范围内，最终补丁生效和运行时消耗未核。
2. `dram_size` 与 owned window 不必相等。生成器要求前者匹配 DTS 单一内存区，后者独立编码为 DarwinBoot 请求，见 `UniXNU/scripts/unixnu/devicetree.py:302-323`；只扩大后者在配置语义上不冲突。实际仍须满足 EFI 连续可分配区、保留区和 UFS DMA 条件。
3. jetsam 同时有内核默认/阈值/执行机制和可由用户态设置的进程策略，不是单纯内核值或 Data plist 值。[XNU limit 处理](https://github.com/apple-oss-distributions/xnu/blob/xnu-10063.141.1/bsd/kern/kern_memorystatus.c#L550-L577) 将 `-1` 解释为系统级 `max_task_footprint_mb`，不是固定 MiB 或必然无限。空 scratch Data 不证明系统卷策略文件不存在，也不证明用户态未设置；r22 初始化值和逐进程最终 limit 未取得，不能给出本机默认 MiB。

除 owned window 外，vnode 压力与 jetsam 进程限额/全局压力阈值均为可能的 SIGKILL 机制，尚无依据排序或定因。现有证据不支持新增具体数值；`sleep-disabled=1` 仅是待板级确认的非内存候选。**只改 owned_memory_size 是否足够：不够确定**；仍缺实际窗口/DMA、jetsam kill reason、进程限额及 vnode/内存水位证据。
